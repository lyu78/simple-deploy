# Стандарт Документации Кода Simple-Deploy

## Назначение

В проекте принят русский язык для модульных и функциональных docstring в коде,
который относится к сборке релизов, SQL-миграциям, локальному состоянию контуров
и Windows-only pipeline.

## Правила

- Модульная docstring объясняет роль файла в общем release/deploy flow.
- Docstring функции описывает ее контракт: что функция принимает, что меняет и
  какое состояние считает источником истины.
- Для функций, которые двигают состояние релизов или контуров, явно указывается,
  меняется ли baseline.
- Для offline SQL generation явно фиксируется, что источник истины - Git range и
  локальный SQLite/manifest, а не реальная БД.
- Если алгоритм best-effort, ограничение описывается прямо в docstring.
- В задачах "только docstring" запрещено менять бизнес-логику, формат данных и
  поведение команд.

## Актуальный стандарт

Документация проекта ведется на русском языке. Для кода, связанного с release/build/deploy, SQL-миграциями, состоянием контуров и Windows-only pipeline, обязательны русскоязычные module docstring и docstring у функций с нетривиальным контрактом.

В docstring для offline SQL generation нужно явно разделять:

- источник истины для генерации: Git range backend source repo;
- источник истины для продвижения релизов: локальная SQLite-база состояния контуров;
- ограничение подхода: SQL строится best-effort без подключения к реальной PostgreSQL;
- смысл manifest: список migration-файлов диапазона `from..to`, а не журнал примененных миграций БД.

Для функций, которые меняют release state, нужно явно писать, обновляют ли они baseline контура, записывают ли попытку применения и какое состояние считается успешным.
