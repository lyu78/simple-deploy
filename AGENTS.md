# Правила для AI-агентов

Этот файл задает рабочие правила для Codex и других AI-агентов в репозитории
`simple-deploy`. Перед изменениями нужно читать `README.MD`, `CONTEXT.MD`,
`DEVELOPMENT_RULES.MD`, `DDD_REFACTORING.MD` и `REFACTORING_PLAN.MD`, если задача
затрагивает архитектуру, пайплайн, документацию или план рефакторинга.

## Граница файлов контекста

- `CONTEXT.MD` хранит проектный контекст: актуальные технические решения,
  контракты, состояние пайплайна, ограничения окружения и важные последствия
  уже принятых решений.
- `AGENTS.md` хранит правила работы агента: как проверять изменения, как
  пользоваться инструментами, что нельзя трогать без явного разрешения.
- Не писать в `CONTEXT.MD` личные настройки машины, временные пути, состояние
  локальных инструментов агента и правила использования браузера. Такие правила
  фиксируются здесь.

## Работа с браузером

- Не использовать основной Chrome, основной профиль пользователя и его
  расширения для автоматизированных проверок.
- Для UI-проверок использовать изолированный Playwright/Chromium с отдельным
  временным `userDataDir`.
- Если нужен локальный браузер агента, устанавливать его вне репозитория,
  например в `%USERPROFILE%\.codex\tools\playwright-runner`, и не добавлять эти
  файлы в Git.
- Не устанавливать и не чинить Codex Chrome Extension или native host в основном
  браузере без отдельного явного разрешения пользователя.
- Если In-app Browser backend недоступен, использовать изолированный
  Playwright/Chromium как fallback для проверки локального UI.

## Проверки

- После изменений в Python запускать релевантные `pytest`-тесты.
- После изменений в React UI запускать `npm run build` в `tools-ci/web-ui`.
- После заметных frontend-изменений проверять UI в изолированном браузере и
  фиксировать в ответе, что именно было проверено.
- Не оставлять запущенные временные dev/backend-серверы после завершения
  проверки.

## Безопасность локального состояния

- Не коммитить реальные `.env`, `local.secrets.env`, ключи, токены, дампы БД,
  логи, локальные state-файлы и временные артефакты.
- Не добавлять в документацию реальные внутренние адреса, логины, домены,
  приватные пути пользователя и имена закрытых сервисов.
- Не откатывать чужие незакоммиченные изменения без явного запроса.
